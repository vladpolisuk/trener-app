# Трекер тренировок — контекст проекта

## Что это
Персональный трекер силовых тренировок для одного пользователя (мужчина, 22 года, цель — рекомпозиция тела: снизить % жира, повысить FFMI с 22 до 23-24). Программа — Full Body 3 дня в неделю (A/B/C), плюс кардио-день и дни отдыха.

Это статичное веб-приложение на трёх файлах (`index.html` / `style.css` / `app.js`) — без сборки, без npm-зависимостей, без бэкенда. Деплоится на Vercel как обычный статический сайт (zero-config). Все данные, включая саму программу тренировок, хранятся в `localStorage` браузера (ключ `fb_tracker_v1`) — синхронизации между устройствами нет, но есть экспорт/импорт в JSON (вкладка Настройки → Данные) для переноса и бэкапа.

## Стек
- Чистый HTML/CSS/JS, без фреймворков и без npm
- Шрифты: Google Fonts (Barlow Condensed для заголовков/цифр, Inter для текста) — подключены через `<link>`
- Хранение: `localStorage`, JSON

## Структура файлов
- `index.html` — разметка: `#app` (контейнер рендера) + нижняя таб-навигация (`data-tab`), подключает `style.css` и `app.js`
- `style.css` — все стили, CSS-переменные в `:root` для светлой/тёмной темы (`prefers-color-scheme` + ручной `data-theme`)
- `app.js` — вся логика:
  1. `DEFAULT_PROGRAM` — дефолтная программа (три дня A/B/C, у каждого массив упражнений); используется только как исходное значение при первом запуске и для кнопки «Восстановить по умолчанию» — **сама программа теперь редактируется пользователем и живёт в `state.program`** (см. «Кастомизация программы» ниже)
  2. `ex(id, name, cat, sets, repMin, repMax, inc, rest)` — фабрика упражнения:
     - `cat`: `'w'` (вес×повторы, большинство упражнений), `'t'` (время в секундах — планка, вис), `'d'` (дистанция+вес — фермерская прогулка)
     - `inc` — шаг прогрессии (кг или сек) при выходе на верх диапазона повторов
  3. `state` / `defaultState()` / `loadState()` / `saveState()` — состояние приложения и работа с localStorage
  4. `getSuggestion(exercise, date, readiness)` — **ядро логики прогрессии** (см. ниже)
  5. `deloadInfo()` — расчёт таймера разгрузочной недели
  6. `render*()` функции — рендер 4 вкладок: Сегодня / Неделя / История / Настройки
  7. `escHtml()` — экранирование пользовательского текста (названия упражнений, дней, отдых) перед вставкой в `innerHTML` — важно, т.к. эти поля теперь редактируются пользователем через UI
  8. Редактор программы (`programEditorCard`, `exerciseEditRow`, `setExField`, `moveExercise`, `deleteExercise`, `addExercise`, `resetProgram`) и экспорт/импорт (`exportData`, `importData`) — см. ниже
- `.claude/launch.json` — конфиг локального статического сервера для превью (`python -m http.server`), используется инструментом предпросмотра, не нужен для самого деплоя
- `favicon.svg` — иконка вкладки/deploy-полировка

## Ключевая бизнес-логика

### Прогрессивная перегрузка (`getSuggestion`)
Двойная прогрессия на основе последней сохранённой тренировки по конкретному упражнению:
- Все подходы достигли верхней границы диапазона повторов → вес +`inc`, повторы вниз к нижней границе
- Хоть один подход не дотянул до нижней границы → тот же вес, тот же нижний таргет (retry)
- Иначе → тот же вес, таргет +1 повтор к предыдущему результату
- Если самочувствие (см. ниже) в среднем ≤2 из 5 — рекомендованный вес снижается на 10%
- Если 2+ тренировки подряд не хватает повторов — показывается предупреждение (`consecutiveFails`)

### Самочувствие (readiness check-in)
Перед тренировкой — 3 шкалы 1-5: сон, энергия, свежесть мышц. Хранится в самой сессии тренировки (`session.readiness`). Влияет на предложенный вес (см. выше).

### Разгрузочные недели (`deloadInfo`)
Считает недели с `lastDeload` (или `cycleStart`, если разгрузок ещё не было) относительно `deloadWeeks` (по умолчанию 7, настраивается в Settings). Если просрочено — баннер на вкладке «Сегодня» с кнопкой «Отметить», которая сбрасывает таймер (`state.lastDeload = today`).

### Расписание недели
`state.scheduleMap` — объект `{0-6: 'A'|'B'|'C'|'cardio'|'rest'}` (0=воскресенье). По умолчанию Пн=A, Ср=B, Пт=C, Сб=cardio, остальное — rest. Редактируется в Settings.

### Кастомизация программы (`state.program`)
Программа тренировок больше не зашита в код — она часть состояния (`state.program`, seed из `DEFAULT_PROGRAM` при первом запуске) и полностью редактируется через Settings → «Редактор программы»:
- Вкладки A/B/C переключают редактируемый день (`progEditorDay`)
- Название и подзаголовок дня — текстовые поля
- Для каждого упражнения: название, тип (`w`/`t`/`d`), подходы, мин/макс повторы, шаг прогрессии, отдых
- Упражнения можно добавлять (`addExercise` — новый id вида `A12` через `genExerciseId`), удалять (`deleteExercise`) и переставлять местами (`moveExercise`, ±1 позиция)
- Удаление упражнения **не трогает историю** — старые сессии остаются в `state.sessions`, но `render*()` функции просто пропускают упражнения, которых больше нет в `state.program[dayKey].exercises` (ищут по `exId`, если не нашли — не рендерят)
- «Восстановить программу по умолчанию» (`resetProgram`) — возвращает `state.program` к `DEFAULT_PROGRAM`, историю не трогает
- Т.к. названия/подзаголовки/отдых — свободный пользовательский текст, все места, где они попадают в `innerHTML`, обёрнуты в `escHtml()` во избежание XSS через собственный ввод

### Экспорт / импорт данных
Settings → «Данные»: `exportData()` скачивает весь `state` (история, программа, расписание, настройки) как `trener-backup-YYYY-MM-DD.json` через `Blob` + временную ссылку. `importData()` читает выбранный файл, проверяет, что это похоже на бэкап (`Array.isArray(parsed.sessions)`), спрашивает подтверждение и заменяет `state` через `Object.assign(defaultState(), parsed)` — как и при обычной загрузке, отсутствующие в файле поля подставляются из `defaultState()`, что даёт обратную совместимость со старыми бэкапами.

## Модель данных (localStorage)
```js
{
  scheduleMap: {1:'A', 2:'rest', 3:'B', 4:'rest', 5:'C', 6:'cardio', 0:'rest'},
  cycleStart: '2026-09-18',      // ISO-дата, старт первого цикла
  lastDeload: null | '2026-09-18',
  deloadWeeks: 7,
  theme: 'auto' | 'light' | 'dark',
  sessions: [
    {
      id: '2026-09-18-A',
      date: '2026-09-18',
      dayKey: 'A',
      readiness: { sleep: 4, energy: 3, soreness: 4 },
      exercises: [
        { exId: 'A1', sets: [ {a: 60, b: 8}, {a: 60, b: 7}, {a: 60, b: 6} ] }
        // a = вес(кг) или дистанция-компонент, b = повторы/секунды/метры
      ]
    }
  ]
}
```

## Известные ограничения / куда двигаться дальше
- **Нет синхронизации между устройствами** — есть только ручной экспорт/импорт JSON (частично закрывает проблему бэкапа/переноса, но не живую синхронизацию). Полноценное решение — облачное хранилище (бэкенд или Firebase) или PWA с сервис-воркером.
- Нет графиков прогресса (веса по времени) — сейчас только текстовая история.
- Нет редактирования уже сохранённого подхода без пересохранения всей тренировки целиком.
- Дни ограничены фиксированным набором A/B/C + cardio/rest — можно редактировать содержимое каждого дня, но не добавить «День D» или изменить набор типов дня в `scheduleMap`.
- Нет PWA-манифеста/service worker — при желании добавить на домашний экран телефона с оффлайн-работой потребуется `manifest.json` + иконки + SW.

## Деплой (Vercel)
Статический сайт, zero-config: `index.html` в корне — Vercel обслуживает его на `/` без каких-либо build-настроек. Локально предпросмотр — `python -m http.server` (см. `.claude/launch.json`) либо просто открыть `index.html` в браузере (без сервера часть функциональности может не работать в некоторых браузерах из-за ограничений `file://`).
